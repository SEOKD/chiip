# ADR-022 알파 감지 축약·경기순환 보정·알파 상승 리포트 갱신

- 상태: 채택(마스터 지시 2026-11-13)
- 범위: `scripts/valuation/v2/alpha_watch.py`·`item_notes.py`·`ib_actions.py`·`plus.py`·`montecarlo.py`·`decision.py`, `scripts/tenbagger/alpha_refresh.py`·`publish_tenbagger.py`

## 1. 알파 감지 텔레그램 축약
구성: 제목 → ☞ 기업 1줄(무엇을 하는 회사 + 밸류체인 위치, `config/company_lines.yaml`) → 왜 감지됐나(자료 줄마다 `→` 한 줄 풀이) → 연 기대수익·안전마진 → 주가 내포 5년 매출 성장 → 내러티브 핵심 → 최근 커버리지(IB 2~3건) → (리포트 갱신 대기열 등록·관찰).
빠진 것(요구수익률 대비·넘을 확률·위험 예산·5년 상방·단계·과밀·＋/－·확인할 것)은 밸류 카드(`outputs/invest/valuation_v2/`)와 리포트에 그대로 있다.

- 한 줄 풀이: 실시간 알림이면 판정 모델이 이미 쓴 `impact`. 수집 항목이면 `item_notes.py` — 레이더 카드 `what_happened` 또는 원문을 결정론으로 가져와 소형 모델(haiku)이 40자 요약 + 알파 관련 여부를 JSON으로 낸다. 본문을 못 가져오면 모델을 부르지 않고 '본문 미확인'. 알파 수치 변화(x→y)는 모델이 아니라 장부로 붙인다. 캐시 `radar/state/alpha_item_notes.json`.
- 기업 1줄이 빈약하면(감시 목록 역할·업종 대체) 대기열 kind '보강' → chiip-valuation-queue가 company_lines와 IB 장부를 채운다.
- IB 커버리지 장부: `knowledge/models/estimates/ib_actions.csv`(날짜·기관·조치·목표가). 라이선스 IB는 메타데이터만.
- 상대방 흔적(`src-partner-trace`·채용 흔적, `trace_query`)은 그 종목의 1차 자료가 아니므로 감지 근거에서 뺀다 — 11/13 'SK하이닉스 + 장비' 검색으로 잡힌 Applied Materials 실적 자료가 SK하이닉스 '새 보도자료'로 나간 오류.

## 2. SK하이닉스 수치 이상(2026-11-13) — 원인과 수정
단위·주식 수·ADR 혼동은 없었다(시총 = 원화 보통주 가격 × 7.05억 주, 컨센서스는 ADR 달러를 ₩1,345로 환산 — 매출은 주당 값이 아니라 ADS 비율 무관). 원인은 모델 쪽 세 가지:
1. **경기순환 정상화 누락**: D3(ADR-016)는 drivers의 `cyclical`이 있어야 켜지는데 `build_drivers`가 이를 쓰지 않아 메모리 종목 어디에도 없었다. → `plus.cyclical_spec`이 감시 목록 업종(`sub`)으로 피어를 고른다(`normalize.peers: memory→MU, storage→WDC`). SK하이닉스 계속가치 마진 42% → MU 10년 평균 24.7%.
2. **마진 충격 2%p 고정**: 영업이익률이 −37%~+75%를 오간 업종에 2%p 잡음만 줘서 하위 10%가 +259%, −30% 확률 0%였다. → 경기순환 종목은 피어 영업이익률 3년 이동평균의 표준편차(MU 14.7%p)로 넓힌다(`prm-dcf-cycle-sigma`).
3. **안전마진 표기**: P10 가치/시총 배수 2.23을 '안전마진 223%'로 썼다. → 그레이엄 정의 1 − 시총/비관 가치(같은 값 55%). 신호 등급 기준(strong_mos)은 배수 그대로.
4. 기저율 백분위 '상위 100%'(내포 −14%)는 거꾸로 읽혀 낮은 쪽을 '과거 기업의 x%가 이보다 높게 성장'으로 쓴다.

수정 전 → 후(3,000회, 11/13): 안전마진 223%(배수) → 9%(배수 1.10) · 하위 10% +259% → +64% · −30% 확률 0% → 4% · 요구수익률 넘을 확률 100% → 88% · 연 기대수익 +37.9% → +31.8% · 내포 5년 매출 성장 −13.7% → −8.2%.
남은 한계: 1~2년차 마진은 컨센서스(82.8%·77.4%) 고정이라 '내년 업황 꺾임' 경로는 bear 시나리오에 없다. 명시적 하강 사이클 시나리오는 후속 과제.

## 3. 알파 상승 리포트 갱신 대기열
- 기준 알파: 최신 리포트 JSON `verdict.alpha`(발행 때 기록). 없으면 그 날짜까지 판단 파일로 재구성(관심 요소 제외, 현재 값도 같은 방식).
- 상승 = 현재 − 기준 − 동시 재산정 쏠림 ≥ +1.0(마스터 값). 쏠림: 같은 산정일 10종목 이상, 중앙 변화 +0.5 이상이면 그 중앙값을 뺀다 — 11/07 일괄 재산정에서 +1.0 이상 상승 21건 중 19건이 한꺼번에 나왔다(121회 전이, 평균 +0.50).
- 최소 간격 14일: 판단 재산정 간격 중앙 9일 → 주간 산정 두 번을 거쳐야 한다. 실적 업데이트(report_refresh)와 겹치지 않게.
- 유지: 처음 충족 = '관찰', 다음 산정(scored_on 변경)에서도 유지되거나 재산정 없이 7일(주 1회 전체 산정 주기) 그대로면 '대기'(등록).
- 처리: 하루 1건, 20시 회차 또는 정기 후보 소진 때, 이미지 지출이 한도 80% 이하이고 월 진행률보다 앞서지 않을 때(아니면 이미지 없이). 실적 업데이트·전문 반영 재발행이 먼저.
- 갱신 리포트: 새 파일(오늘 stem), 맨 앞 '갱신 사유' 절(전→후 알파, 유지 근거, 이전 판 링크 = Artifact + 커밋 고정 GitHub 주소 — 옛 날짜 파일은 prune_reports가 지우고 노션은 종목당 한 페이지라 링크가 될 수 없다, 핵심 수치 비교 표). 게시는 GitHub+노션 그대로, 텔레그램 머리 '[갱신 — 알파 x → y]'(`send --update`).
- 자동 실행 금지 범위: 대기열 등록과 표시까지는 자동, 리포트 작성은 예약 작업 chiip-tenbagger-report 회차가 한다.

## 반증·재검토 조건
- 갱신 리포트가 등급·목표주가를 거의 바꾸지 못하면(판단 변경률 낮음) RISE·MIN_GAP을 올린다(등록부 prm-refresh-*).
- 경기순환 σ로 메모리 종목 하위 분위가 실현보다 계속 비관적이면 sigma_window를 늘린다.
