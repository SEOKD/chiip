# ADR-015 학회 참여 추적 파이프라인(삼성·SK·LG)

- 날짜: 2026-11-05 · 결정: 마스터 지시 · 상태: **설계안(마스터 승인 대기)** — 승인 전에는 수집 코드를 만들지 않는다
- 지시: "이 학회들의 자료와 세미나 프로그램을 보고 삼성, SK, LG 관계자가 참석하거나 논문을 게재한 사례를 모두 찾는 파이프라인을 설계하라. 체계적인 접근법을 접목해야 한다. 기사 소재 발굴 등에 써라. 삼성전자, SK하이닉스가 참여하는 학회가 더 있는지도 추가 리스트업하라."
- 학회 정본: `config/conferences.yaml`(마스터 목록 + 추가분 `added: true`). 기존 스킬 `conference-tracker`는 이 파이프라인의 '판단' 단계로 흡수한다.

## 왜 학회인가 — 역방향 레이더 명제와의 연결
- 학회 논문은 **서류**다. 제출 마감은 발표보다 4~8개월 앞서고, 프로그램 공개는 발표보다 1~3개월 앞선다. 회사 보도자료보다 먼저, 숫자(밀도·속도·층수·전력)를 붙여 나온다.
- 같은 세션의 경쟁사(마이크론·TSMC·인텔·CXMT·YMTC·키옥시아) 논문과 **나란히 비교**할 수 있는 드문 장소다.
- **침묵도 신호다**: 매년 내던 트랙(예: ISSCC DRAM 세션)에서 한 회사가 빠지면, 그 자체가 확인 질문이 된다.
- **공저 관계**는 공급 관계의 흔적이다(고객사·장비사·대학 공저). 단 공저 → 공급 계약은 금지표 연결이다. 정황으로만 쓴다.

## 파이프라인 7단계 (수집은 결정론 스크립트, 판단만 모델)

| 단계 | 하는 일 | 산출 | 주기 |
|---|---|---|---|
| 0 등록부 | 학회별 분야·개최월·프로그램 URL·초록 출처·접근 방법·등급 | `config/conferences.yaml` | 분기 점검 |
| 1 일정 | 제출 마감·프로그램 공개·개최일을 공식 사이트에서 확인해 일정에 올린다 | `knowledge/calendar.csv` (`type: conference`) | 월 1회 |
| 2 수집 | 프로그램·초록 **메타데이터**만(제목·소속·세션·초록 요지·링크) | `radar/conferences/inbox/<cf-id>.jsonl` (git 제외) | 프로그램 공개 후 주 1회, 개최 주간 매일 |
| 3 소속 매칭 | 사전·ROR ID로 삼성·SK·LG 계열사를 판정하고 오탐 규칙 적용 | 행마다 `org`, `unit`, `match_conf` | 수집 직후 |
| 4 분류 | 역할·주제·숫자·경쟁 비교·전년 대비 | `knowledge/entities/conferences/<cf-id>_tracker.md` | 수집 직후 |
| 5 신호 채점 | 기사 가치·신규성·침묵·공저 점수 | 점수 열 + 상위 후보 | 수집 직후 |
| 6 출력 | 기사 소재·논문 요약 대기열·주장 승격·텔레그램 | `article-pitch` 후보, `paper-digest` 대기열 | 점수 문턱 통과 시 |
| 7 평가 | 과거 3년 백테스트로 재현율·정확도·선행 일수 측정 | `evals/conferences/backtest.csv` | 최초 1회 + 분기 |

### 2. 수집 원천 (우선순위)
1. **공식 프로그램 페이지·초록집**: 세션 표, 기조연설·패널·튜토리얼 명단. robots.txt와 약관을 지키고, 로그인이 필요한 초록집은 쓰지 않는다.
2. **서지 메타데이터 API**
   - 출판본: OpenAlex(소속 기관 ROR ID 검색, 기존 `radar/reverse/collectors/openalex.py` 확장)와 Crossref(DOI·발간일).
   - 분야별:
     - IEEE Xplore Metadata API: ISSCC·IEDM·VLSI·ECTC 등. 키 필요(마스터 몫).
     - DBLP: ISCA·MICRO·HPCA·DAC·ICCAD·ASPLOS·NeurIPS 등 CS 계열.
     - arXiv: 학회 전 사전 공개본.
     - SPIE Digital Library: 메타데이터만.
3. **기업 1차 채널**
   - 뉴스룸·기술 블로그: 삼성 뉴스룸, SK하이닉스 뉴스룸, LG 각 사 보도자료. "○○ 학회에서 발표" 공지가 대상이다.
   - 학회 스폰서·전시 명단.
4. **언론 대조**: 국내외 보도. 보도는 확인 수단이지 원천이 아니다(`origin_id`로 재인용을 묶는다).
5. **공개 동영상·슬라이드**: 학회가 공개한 것만, 메타데이터와 링크로.
- 유료벽 원문은 복제·우회하지 않는다. 마스터가 받은 원문은 `D:\local-only\licensed\`에 두고, 저장소에는 요약만 남긴다.

### 3. 소속 매칭 — 체계
- **기준 사전**: `config/lexicon/co-samsung.yaml`·`co-skhynix.yaml`·`co-lginnotek.yaml` 등에 `affiliations:` 키를 더한다. 표기는 한·영·중·일 4개 언어로 두고, 대표 예는 다음과 같다.
  - Samsung Electronics: Memory, Foundry, System LSI, SAIT(종합기술원), Samsung Research
  - SK hynix: 미국·이천·청주 사업장
  - LG: LG Electronics(SoC Center 등), LG Innotek, LG Display, LG Chem, LG AI Research
  - 계열사 확장: 삼성전기·삼성디스플레이·삼성SDI·SK실트론·SK키파운드리·SK스페셜티·SK텔레콤(AI 반도체)·사피온 합병사
- **기관 ID 우선**: OpenAlex·ROR 기관 ID가 있으면 문자열보다 먼저 쓴다. 문자열 매칭은 보조다.
- **오탐 규칙**:
  - "Samsung Medical Center/Hospital", 삼성중공업·삼성생명은 반도체 무관으로 표시한다.
  - "SK"·"LG"는 단독 토큰만으로 매칭하지 않는다.
  - 대학 산학 과제의 "Sponsored by Samsung"은 `role: funding`으로 따로 분류한다.
- **매칭 신뢰도**: `A`(기관 ID 일치) / `B`(정식 소속 문자열) / `C`(약칭·감사의 글) — C는 사람 확인 전 출력하지 않는다.

### 4. 분류 축
- **역할**: 제1저자 소속 / 공저 / 기조연설 / 초청 강연 / 패널 / 튜토리얼 / 프로그램 위원 / 전시·스폰서 / 연구비 지원.
- **주제**: 분야 모듈과 같은 체계로 나눈다.
  - DRAM·HBM / NAND / 파운드리·로직 / 패키징 / 장비·소재 / 네트워킹 / AI 가속기 / 전력 / 수동소자 / 기기
  - 분류 결과는 `config/keywords.yaml`과 연결한다.
- **숫자 추출**: 밀도(Gb), 속도(Gbps·GT/s), 층수, 노드(nm), 전력(pJ/b), 면적, 수율 언급. 단위와 제품 세대를 같이 적고, 다른 세대끼리는 비교하지 않는다.
- **전년 대비**: 같은 학회의 과거 3년 행과 비교해 새 주제, 사라진 주제, 숫자 개선 폭을 본다.

### 5. 신호 채점 (기사 가치)
| 신호 | 의미 | 예 |
|---|---|---|
| 최초 공개 숫자 | 회사 보도자료에 없는 사양 | HBM 다음 세대 I/O 속도 |
| 경쟁 정면 비교 | 같은 세션에 경쟁사 같은 주제 논문 | ISSCC DRAM 세션 3사 |
| 침묵 | 3년 연속 내던 트랙에서 빠짐 | 특정 메모리 세션 부재 |
| 공저 | 고객사·장비사·해외 대학과 공저 | 빅테크 공저 → 정황 |
| 첫 진입 | 처음 보는 학회·분야 | LG의 칩렛·광 인터커넥트 |
| 무게 | 기조연설·Late-breaking·하이라이트 논문 선정 | IEDM 하이라이트 |
- 점수는 결정론 가중합으로 계산한다. 가중치는 `registry.yaml`에 사전값으로 등록하고(`prm-conf-*`), 백테스트로 피팅한다.
- 상위 후보만 모델이 `yama-check`로 판정한다.

### 6. 출력과 경계
- **기사 소재**: `article-pitch` 입력에 `conference` 원천을 더한다. 야마 1문장, 비교표, 확인 취재 질문을 붙인다.
- **주장 승격**: 프로그램·초록은 S3(1차 서류)이므로 `claim-intake` 대상이 된다. 유형은 '가이던스·추정'이 아니라 '학회 발표(연구 결과)'다.
  - 금지표 '샘플 출하 → 양산 성공'과 같은 방식으로, **학회 발표 → 양산·채택**은 연결하지 않는다.
  - 상용화 상태는 제조·고객·사업 세 축을 따로 적는다.
- **사람 정보**:
  - 임원, 기조연설자, 패널 등 공개 직책자만 이름을 쓴다.
  - 일반 연구원 저자는 저장소에 이름을 쓰지 않고 **집계**(학회·회사·조직·주제별 편수)로만 남긴다. 링크로 원문 서지에 접근할 수 있으므로 이름 복제가 필요 없다.
- **알림**: 프로그램 공개와 고득점 후보만 텔레그램 개인 봇으로 보낸다. 반복 보도는 보내지 않는다.

### 7. 평가
- 백테스트 대상: ISSCC·IEDM·VLSI·ECTC·Hot Chips의 2023~2025년. 정답지는 공식 프로그램의 삼성·SK·LG 소속 논문 수다.
- 지표:
  - 매칭 재현율·정확도
  - 기사화된 건 대비 선행 일수(프로그램 공개일 → 첫 국내 보도일)
  - 기사 소재 채택률. 성적표와 연결한다.

## 운영 주기
- 상시: 월 1회 일정 점검, 학회별 프로그램 공개일 감시. 페이지 변화 감시(`page-diff-review`)를 재사용한다.
- 공개 직후: 수집 → 매칭 → 채점 → 추적표 → 상위 3건을 기사 소재로.
- 개최 주간: 매일 보도·슬라이드 공개를 대조한다. 마스터 현장 취재는 `field-intake`(등급 판정)로 받는다.
- 우선 구현 순서(1차 15곳): ISSCC, IEDM, VLSI, Hot Chips, ECTC, IMW, FMS, SPIE AL, OFC, IRPS, ITF World, OCP, SEMICON Korea STS, KCS, ISOCC.

## 대가·제약
- IEEE Xplore API 키 발급은 마스터 몫이다(`docs/TODO_MASTER.md`). 키가 없으면 OpenAlex와 공식 프로그램만 쓰고, 재현율이 낮아질 수 있다.
- 기업 비공개 포럼(예: 파운드리 고객 전용 세션), 회원 전용 워크숍(SISC 일부)은 수집하지 않는다.
- 학회별 프로그램 형식이 제각각이다. 파서는 학회마다 작게 만들고 실패하면 경보를 보낸다(자동 복구 `self_heal` 대상).
- 추가 학회 목록의 개최월은 공식 사이트로 확인하기 전에는 비워 둔다(1단계에서 채운다).
