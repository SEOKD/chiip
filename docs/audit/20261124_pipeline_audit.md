## 4. 설계안과 반영
### D1 모델 사용 한도 관리 — `radar/model_budget.py`(새 파일)
- 문제: 한도 문구에 재개 시각이 있는데(예: "resets 4pm (Asia/Seoul)") 아무도 읽지 않았다. 문턱은 헛회차로 상한을 채웠고, 노션 감시는 자료를 버렸다.
- 설계: 실패 문구에서 한도를 읽어 재개 시각(+3분)까지 대기 상태를 둔다. 헤드리스 실행기는 띄우기 전에 `guard()`로 확인한다. 한도 실패는 `Hold`(실패가 아니라 대기)로 던져 작업을 남긴다. 알림은 한도 구간마다 한 번.
- 반영: `pulse_trigger`(대기 중엔 띄우지 않고 상한도 세지 않음, 실패 문구를 장부에 남김, 상한 알림 문구 바로잡음), `run_triage.run_claude`(헤드라인 알파·빠른 판정·영향 카드·IPO·항목 노트가 함께 쓰는 실행기), `notion_watch`(대기면 실패 표시 없이 대기열에 남김), `article_draft`.
- 문구 두 가지: 앱 예약은 "You've hit your Fable limit · resets 4pm (Asia/Seoul)"(재개 시각 있음)이다. 헤드리스(`claude -p`)는 "You've reached your Fable limit. Switch to another model…"(재개 시각 없음, 11/24 08:57 장부)이다. 재개 시각이 없으면 1시간 대기 뒤 한 번만 다시 띄워 본다. 같은 한도 구간에서는 알림을 다시 보내지 않는다.
- 한계: 앱 예약 회차는 앱이 직접 띄우므로 막지 못한다(한도 동안 바로 실패해 비용은 없다). 한도는 문턱의 헤드리스 실패로 처음 감지된다.

### D2 Pulse 관문 — 어닝콜 전문 확인 간격 단계화 + 회차 효율 지표
- 근거: 찾은 전문 121건의 게재 지연은 중앙 8.1시간, 90% 11.9시간, 24시간 안 99%, 48시간 안 100%. 그런데 10일 동안 20분마다 확인했다.
- 반영: `transcript_watch.STEPS` — 콜 종료 뒤 24시간 안 20분, 48시간 안 2시간, 그 뒤 12시간(10일 대기는 그대로). `run_ledger --report`에 `pulse`(모델 회차·발송 회차·효율·회차를 연 이유 상위 10)와 `headless`(실패·한도 대기) 지표를 더했다. Model Laboratory agent 절차(2번)가 이미 이 보고를 읽는다.
- 보지 않은 것: 텔레그램 채널별 채택률(7일 2,120건 중 13건 채택, 0건 채널 다수)로 채널을 묶어 판단하는 안. 회차를 연 이유가 채널 글이 아니어서 효과가 작다(묶어도 회차 3~9%만 줄어듦). 보류.

### D3 긴 수집 작업 시간 한도 — `radar/run_hourly.py` `HEAVY`
- 반영: trade-ppi·trade-hs·src-attention·jp-ir-audit은 25분 한도로 돌린다. 예산이 그만큼 남은 회차에만 시작하고, 모자라면 다음 회차로 미룬다(밀린 비율이 커져 곧 맨 앞에 선다). Windows 작업 30분 한도 안이다.
- 확인 대기: 25분 안에 끝나는지는 다음 회차의 health 기록으로 본다. 넘으면 작업을 나눠 이어받게 고쳐야 한다.
- 결과(11/24 12:01): trade-ppi가 25분에도 끊겼다(44개 입력 × 7개국 Comext + HMRC·Census·e-Stat). 이어받기로 고쳤다 — `radar/resume.py` 커서가 단계(trade-ppi 입력 하나, trade-hs 묶음 하나, src-attention 종목 하나)를 마칠 때마다 결과를 `radar/state/resume_<이름>.json`에 적고 다음 회차는 끝난 단계를 건너뛴다. 시간 초과 때 진행이 늘었으면 run_hourly가 하루 뒤가 아니라 120분 뒤에 다시 돌린다(`RESUMABLE`·`RETRY_MIN`). 진행이 그대로면 예전처럼 다음 날 — 막힌 원천이 매 회차를 잡아먹지 않게. 설정이 바뀌거나 주기 시작이 이틀을 넘으면 처음부터. src-attention은 한 주기의 줄을 주기 시작일로 적는다. 시험 `tests/test_resume.py`.

### D4 예측 판정 고리 — `scripts/score_predictions.py`, `.claude/skills/model-lab/SKILL.md` agent 8번
- 반영: 형식 검사 `--check`(칸 수·기한·확률·주체·판정값 1/0), 판정 대기 목록 `--due N`. Model Laboratory가 매일 하루 5건까지 1차 출처로 판정한다(그 행의 resolved_on·outcome·notes만). '치입'·'Chiip' 표기를 한 주체로 묶어 채점한다. 사후 수정 금지 원칙대로 칸이 밀린 행은 고치지 않고 알리기만 한다.
