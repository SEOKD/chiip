'사라/팔아라'·목표주가·비중 표현 금지 — 가치는 시가총액 대비 배수와 확률로만. 기저율은 숫자로 쓴다(10배는 희귀 사건). **논문 표기('저자 연도')는 리포트 어디에도 쓰지 않는다**(2026-10-30 마스터 지시 — 렌더러가 괄호째 지우고, 괄호 밖에 남으면 렌더가 실패한다).

4. **상단 표기(마스터 지시 2026-10-29)**: verdict의 confidence는 **컨빅션**(고·중·저, 같은 체계), insight는 **알파**(10점, 같은 체계)로 렌더된다. 업사이드(+%)는 verdict.upside(소수, 예 0.28)와 upside_basis를 쓰거나, 없으면 렌더러가 판단 시나리오 확률 가중값 ÷ 현재값 − 1로 계산한다(기간·할인 여부를 basis에 적는다). 'v2 기본'·'MC P50' 같은 내부 약어를 쓰지 말고 'DCF 내재가치(기본)'·'몬테카를로 중앙값'처럼 풀어 쓴다(렌더러가 남은 약어도 바꾼다). 그래프는 렌더러가 전부 'Chiip View·한 장 요약' 바로 아래 '한눈에 보기'로 모으고 본문에는 그림 번호 링크만 남긴다 — 그래프 제목만 보고도 무엇인지 알게 단위·기간을 제목에 적는다. 그래프 아래 설명은 그림 5의 사건 번호 설명과 몬테카를로 해석(읽는 법·지금 주가 이상 비율과 범위·k배 횟수, `ladder.mc_reading`이 자동 생성)에만 넣는다(2026-10-30 마스터 지시). **그림 번호 고정**(2026-10-30 마스터 지시): 그림 3 = 가격 내포 기대 vs 필요 성장, 그림 5 = 지난 12개월 EPS 리비전 추이, 그림 8 = 최근 4개 분기 주가 분해. 차트의 `pin`으로 엔진이 꽂는다. 모델은 '지금 가격이 가정하는 값 vs 가이던스' 그림을 그리지 않는다(같은 숫자는 표로).
4-1. JSON 쓰기: outputs/tenbagger/reports/<YYYYMMDD>_<티커>.json — 구조는 `scripts/tenbagger/report_html.py` 맨 위 설명(필수: title·date·ticker·company·biz). **요약·절 순서**(2026-10-30 마스터 지시): 한 장 요약 ① 기업가치를 결정하는 내러티브 ② 배수 사다리는 엔진이 맨 앞에 넣는다 — 모델은 그다음 항목(지금 가격의 가정·콜 변화·주가 원인·판단 변화 조건)과 절(주가와 배수·실적·사업과 병목·손익분기·시나리오·반대 검증·킬 조건)만 쓴다. 번호는 엔진이 다시 매긴다. 차트는 최소 3개: ① 주가(line) ② 분기 매출·이익 실적+컨센서스(bars) ③ 시나리오(scenario). 핵심 변수 손익분기(hbars)·경쟁사 비교(hbars/table) 권장. 본보기 `outputs/tenbagger/reports/20261029_CBRS.json`. 숫자는 단위를 제목에 적는다. **달러 금액은 $25B·$340M·$1.2T 표기**(마스터 지시 2026-10-29 — '250억$' 금지, million=M·trillion=T. 렌더러와 텔레그램 발송이 radar/units.py로 한 번 더 바꾸지만 처음부터 이렇게 쓴다). 엔·원은 억 엔·조 원 그대로. 추정·자체추론은 '추정'이라고 쓴다. **굵게**만 쓸 수 있고 HTML 태그는 쓰지 않는다.

5. 밸류에이션 절 병합 → 그리기·확인: `py scripts/tenbagger/v2_to_report.py <id> --merge <json>` 다음 `py scripts/tenbagger/report_html.py <json>` → .html. 출력에 오류가 없고 파일이 생겼는지 확인한다(차트 수 = svg 수).

6. **발행 — GitHub(보는 링크) → 노션 → 텔레그램을 한 묶음으로**(마스터 지시 2026-10-30 "리포트 결과물을 볼 수 있는 github 링크를 제공해야지. 비공개 저장소 링크를 누르니 코드밖에 안 뜬다. 노션에도 결과물이 Github와 동시에 올라와야 한다" → 설계 승인). 텔레그램은 GitHub·노션 결과가 기록된 뒤 마지막에 한 번만 보낸다. 마스터는 모바일로만 본다.
   a. 캡션 파일 outputs/tenbagger/reports/<YYYYMMDD>_<티커>_caption.txt(1,000자 이내): `[Chiip Ten-bagger Report MM/DD] 회사(티커) — 제목` / `기업: 사업 1줄` / `Chiip View: … · 컨빅션 고/중/저 · 알파 x/10 · 업사이드 +x%` / `밸류: DCF 내재가치(기본) x배·몬테카를로 중앙값 x배(배 = 주주가치 ÷ 시가총액)·시장 내포 5년 매출 CAGR x% · 판단 시나리오 확률 가중 x배` / `수급: 리테일 거래 몫 x% · 기관 CMF ±x / 가격 구간: 저항 $a~b · 지지 $c` / `킬 조건 1개 · 다음 확인 사건(날짜)` / Zacks 수치를 썼으면 `Data provided by Zacks Investment Research, Inc., www.zacksdata.com` / `연구 후보이지 매수 권유 아님 · 1차 판정, 미검증`. 링크는 넣지 않는다(발행 스크립트가 붙인다).
   b. GitHub: `py scripts/tenbagger/publish_tenbagger.py prepare <json> --extra knowledge/models/companies/<id>/datapack.json knowledge/models/companies/<id>/drivers.yaml` — 마크다운 판(그림이 그 자리에 보이는 `<이름>.md` + `charts/<이름>_n.svg`, `report_md.py`)·HTML·JSON을 claude/reports 브랜치에 올리고 노션 본문(_notion.md, GitHub 보기 링크 포함)을 만든다. 출력의 `github_md`가 마스터가 누를 보기 링크(비공개 저장소의 HTML은 소스로만 보이므로 HTML 링크는 보관용). 실패하면 텔레그램을 보내지 않고 오류 한 줄을 기록한 뒤 끝낸다(다음 회차 pending).
   b2. **보기 링크 = claude.ai 비공개 Artifact**(마스터 지시 2026-10-30 "리포트 링크는 Github .md 말고 html로" — 비공개 저장소 HTML은 GitHub에서 소스로만 보여서): Artifact 도구로 출력 `artifact_page`(<이름>_artifact.html — 게시용 판, 짧은 title·여백 메타 포함)를 게시한다. 첫 게시는 `icon: "chart"`와 한 문장 description(`회사(티커) 텐배거 리포트 날짜 — 밸류에이션·수급·가격 구간·시나리오 (연구 후보이지 매수 권유 아님)`). 출력 `artifact_url`이 이미 있으면(정정 재발행) 그 URL을 먼저 Artifact `read`로 읽고 `url` 인자로 같은 주소에 다시 게시한다. 성공: `py scripts/tenbagger/publish_tenbagger.py artifact <json> --url <claude.ai 링크>`. Artifact 도구가 없거나 실패하면 `… artifact <json> --fail "<이유>"` — send가 GitHub 마크다운 링크로 대신하고 '보기 링크 게시 실패'를 붙인다.
   c. 노션(같은 회차 안에서 반드시): ① HTML을 노션에 올린다 — 출력 `html_kib`가 200 이하면 `notion-create-attachment`(content = HTML 파일 전체, filename `<이름>.html`), 넘으면 `notion-create-file-upload`(filename `<이름>.html`) 후 받은 upload_url로 curl 멀티파트 POST(`file` 필드, upload_headers 모두) → `notion-create-attachment`(source_file_id). 응답의 markdown_source로 `<embed source="file-upload://…" />` 한 줄을 만든다(HTML은 임베드로만 — 코드·파일 블록 금지). ② 본문 = 임베드 줄 + 빈 줄 + _notion.md 내용. ③ 출력 `notion_existing_page`가 있으면 그 페이지 내용을 이 본문으로 바꾸고(정정·재발행), 없으면 Stocks 페이지(config/notion.yaml pages.stocks) 아래에서 제목에 그 **티커**가 들어간 종목 페이지를 찾아(없으면 '<한국어 회사명> <티커>'로 만든다 — 마스터가 쓴 본문은 고치지 않는다) 그 아래 하위 페이지로 제목 = 출력 `notion_title`. ④ 성공: `py scripts/tenbagger/publish_tenbagger.py notion <json> --page <리포트 페이지 URL> --stock-page <종목 페이지 URL>`. 실패: 한 번 다시 시도하고 그래도 안 되면 `… notion <json> --fail "<이유 한 줄>"`.
   d. 텔레그램: `py scripts/tenbagger/publish_tenbagger.py send <json> --caption <캡션 파일>` — 캡션 + `📄 리포트 보기`(Artifact) + `🗂 노션` 링크. GitHub는 보관용(HTML·마크다운·데이터)이라 텔레그램에 넣지 않는다. 노션이 실패로 기록돼 있으면 '노션 게시 실패 — 다음 회차에 다시 올립니다'를 붙여 보낸다. HTML 파일은 보내지 않는다.
   e. **회차 시작 때 먼저**: `py scripts/tenbagger/publish_tenbagger.py pending` — Artifact·노션 미완료·텔레그램 미발송 리포트가 있으면 b2(Artifact)·c(노션)·d(send — 이미 보낸 리포트면 '노션 게시 완료' 한 줄만 간다)부터 마친다.
7. 기록: `py scripts/tenbagger/pick_report.py --done <id> <티커> <html 경로> "<치입 판단 한 줄>"`. 처음 다루는 후보면 knowledge/models/tenbagger/watch.csv에 등록일 가격과 함께 한 행 추가(tenbagger-card 규칙), 측정 가능한 예측 1개를 knowledge/predictions.csv에(owner 치입, origin 리포트 파일). 기업 사업 설명이 config/company_lines.yaml에 없으면 한 줄 추가.
