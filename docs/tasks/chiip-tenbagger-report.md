   c. 노션(같은 회차 안에서 반드시, b2 다음): ① **html 링크만 올린다**(마스터 지시 2026-11-04 "Notion에는 html 링크만 업로드") — 본문 = `py scripts/tenbagger/publish_tenbagger.py notion-text <json>`이 내는 한 줄 그대로. md 본문(_notion.md)·HTML 임베드·파일 첨부는 올리지 않는다. ② Artifact 링크가 없으면 notion 단계가 멈춘다 — b2를 먼저 끝낸다. ③ **종목당 리포트 페이지는 하나다**(마스터 지시 2026-11-02 "새로 업데이트한 리포트는 노션에 저장할 때 기존 링크를 덮어라. 덮으면 기존 링크는 사라지도록 하라"). 출력 `notion_existing_page`가 있으면 날짜가 달라도 그 페이지 내용을 이 본문으로 바꾸고(`replace_content`) 제목도 출력 `notion_title`로 바꾼다(`update_properties`). 없으면 Stocks 페이지(config/notion.yaml pages.stocks) 아래에서 제목에 그 **티커**가 들어간 종목 페이지를 찾아(없으면 '<한국어 회사명> <티커>'로 만든다 — 마스터가 쓴 본문은 고치지 않는다) 그 페이지를 읽는다. 하위에 '텐배거 리포트' 페이지가 있으면 같은 방식으로 덮어쓰고, 없을 때만 새 하위 페이지를 만든다(제목 = 출력 `notion_title`). 하위 리포트가 둘 이상이면 덮어쓴 페이지만 남기고 나머지는 `notion-delete-pages`로 휴지통에 옮긴다. ④ 성공: `py scripts/tenbagger/publish_tenbagger.py notion <json> --page <리포트 페이지 URL> --stock-page <종목 페이지 URL>`. 기록된 페이지와 다른 페이지를 내면 스크립트가 멈춘다 — 옛 페이지를 휴지통으로 옮긴 뒤에만 `--replaced`를 붙인다. 실패: 한 번 다시 시도하고 그래도 안 되면 `… notion <json> --fail "<이유 한 줄>"`.
   c2. **신호 가격 → TradingView 알림**(마스터 지시 2026-11-04 "밸류에이션·차트 지지선·저항선을 종합해 Buy·Sell 신호 가격을 TradingView 종목별 알림에 — 최종 판단 책임은 마스터"): 발행 뒤 `py scripts/tenbagger/price_levels.py --symbols`의 심볼을 TradingView `mcp-tv-get-symbol-data-batch`(같은 출력의 columns, 한 번에)로 받아 파일 저장 → `--compute <파일>` → 출력 plan의 `stop`은 `mcp-tv-stop-alerts`로 멈추고(지우지 않는다), `create`는 이번 리포트 종목과 아직 알림이 없는 종목부터 회차당 최대 8건 `mcp-tv-create-alert`(symbol·price·condition·resolution 1D·name·message 그대로, 한 번에 하나씩) → 받은 alert_id를 `{"TICK": {"buy": [id, 가격], "sell": [id, 가격]}}`로 `--record`. 알림 문구에 '연구 지표 — 최종 판단과 책임은 마스터'가 들어 있다(바꾸지 않는다). 리포트 본문·텔레그램에는 신호 가격을 '신호 가격(연구 지표)'으로만 쓴다.
   d. 텔레그램: `py scripts/tenbagger/publish_tenbagger.py send <json>` — 결론·이유·밸류에이션·셀온 조건·다음 확인 + 리포트 보기(GitHub 마크다운)·노션 링크. 노션이 실패로 기록돼 있으면 '노션 게시 실패 — 다음 회차에 다시 올립니다'를 붙여 보낸다. HTML 파일은 보내지 않는다.
   e. **회차 시작 때 먼저**: `py scripts/tenbagger/publish_tenbagger.py pending` — 노션 미완료·텔레그램 미발송 리포트가 있으면 c(노션)·d(send — 이미 보낸 리포트면 '노션 게시 완료' 한 줄만 간다)부터 마친다.
7. 기록: `py scripts/tenbagger/pick_report.py --done <id> <티커> <html 경로> "<치입 판단 한 줄>"`. 처음 다루는 후보면 knowledge/models/tenbagger/watch.csv에 등록일 가격과 함께 한 행 추가(tenbagger-card 규칙), 측정 가능한 예측 1개를 knowledge/predictions.csv에(owner 치입, origin 리포트 파일). 기업 사업 설명이 config/company_lines.yaml에 없으면 한 줄 추가.

금지: D:\local-only 읽기, 필드 인텔·채널체크 사용(노션 Exclusive Source 단서는 `docs/channels/notion.md`대로), 로그인·유료벽 우회, robots.txt가 막은 사이트 접속, 원문·트랜스크립트 전체 복제, '사라/팔아라/보유하라' 문장·비중 지시, 규칙 밖의 등급 변경, 공개 채널 게시, 확인 안 된 단정. 구매 등급과 시나리오 주가는 엔진 계산값만 쓴다.
git 커밋·푸시는 하지 않는다(예외: publish_tenbagger.py·publish_report.py가 claude/reports 브랜치에 리포트 파일만 올리는 것). main은 마스터 세션에서 일괄 커밋한다.

## 프로바이저 보강
매 회차 시작 전에 `docs/proviser/chiip-tenbagger.md`의 '상시 원칙'과 '현재 보강 지시'를 읽고 적용한다(이 리포트는 Chiip ten-bagger 기능의 일부). 리포트 '출처' 끝에 `보강 적용: D-…`를 적는다.

**데이터 채널 장애(마스터 지시 2026-11-02):** Fiscal.ai·Zacks·Easyconomics·TradingView 호출이 오류를 내면 `py radar/self_heal.py --report <fiscal|zacks|easyconomics|tradingview> "오류 내용"`을 남기고 `docs/channels/data.md` 순서대로 다음 채널을 쓴다. 키나 토큰 값은 적지 않는다. **Fiscal.ai 연결 자체가 죽었을 때(2026-11-14 점검):** 10분 뒤 한 번 더 부르고, 그래도 안 되면 `config/data_sources.yaml` `outage.fiscal.routes`의 항목별 대체 원천(TradingView 재무·추정, Easyconomics 재무제표·전사, SEC XBRL)으로 진행한다. 대체 원천을 쓴 칸은 datapack sources에 '대체 원천'으로 적는다. Fiscal 자체 추정·Forward 배수 이력처럼 대체가 없는 칸 때문에 막히면 그 종목은 `--done` 없이 다음 회차로 미룬다(리포트 0건으로 끝내기 전에 다른 종목·재발행 건을 먼저 본다).

**HS 급등 품목(2026-11-02 마스터 지시):** `py radar/trade_hs.py --surge`(급등 품목), `--series <hs>`(시계열), `--company <회사 id>`(이 회사 BOM 품목과 겹치는 급등)를 필요할 때 본다. 수출입 급등은 단서이고 금지표대로 특정 기업 매출로 바로 잇지 않는다. 금액 증가는 가격과 물량을 나누지 않은 값이다.

**시설 위성 판독(2026-11-03 마스터 지시):** 소유 공장·데이터센터가 있는 회사는 `capacity.sites`에 시설 id를 쓴다. 소유 시설이 없으면 `capacity.sites_none`에 이유를 쓴다. 등록 절차:
1. 10-K 설비 항목·회사 발표로 시설을 찾아 `knowledge/models/sites/<회사 id>.yaml`에 쓴다(구조는 `scripts/tenbagger/site_view.py` 맨 위). 소유·임차를 구분하고 위치 근거를 적는다.
2. `py radar/site_imagery.py --site <id>`로 영상·건물 윤곽을 받는다. 건물 이름이 없으면 `--grid <id> [날짜]` 영상을 보고 `--measure <id> <날짜> x,y x,y…`로 윤곽을 재서 `polygon`으로 쓴다.
3. 처음과 최신 영상을 직접 보고 호기마다 `stage_seen`·`seen_on`·`seen_note`를 쓴다. 보이지 않는 것은 쓰지 않는다. 10m 영상에서 안 보이면 낮은 단계로 쓴다.
4. 캐파가 공시된 호기는 `capacity`에 출처와 함께 쓴다. 공시가 없는 호기는 비워 두면 엔진이 면적 비교로 추정한다. 비교 시설이 없으면 같은 class의 공시 시설을 등록부에 더한다.

**로비 내역(2026-11-03 마스터 지시):** 미국 상장 종목은 먼저 Easyconomics `insider_and_politics`(section lobbying, ticker)를 받아 파일로 저장하고 `py radar/usgov/lobby_watch.py --put-house <회사 id> <티커> <파일>`로 넣는다(2026-11-08 — lda.gov가 한국 접속을 막아 하원 LD 분기 집계로 대신한다. 분기 지출·전 분기 대비·쟁점 코드까지이고 로비 회사·법안명은 없다). 이어서 종목마다 `py radar/usgov/lobby_watch.py <회사 id> "<공시상 회사명>" [자회사·별칭]`을 돌리고 `knowledge/models/lobby/<회사 id>.json`을 읽어, 경영진 또는 약세 논리에 쓸 내용이 있을 때만 쓴다. verdict가 '미확인'이면 로비가 없다고 쓰지 않는다. SEC 검색 결과와 언론 제목은 단서이므로 원문을 확인한다.
