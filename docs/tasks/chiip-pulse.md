1. ① 미보도 원문 — 최대 3건, 어디에도 보도되지 않은 것만.
   - 최선을 다해 찾는다: sources를 점수 상위만 보지 말고 유형별(공시·보도자료·논문·정부)로 끝까지 훑는다. 8-K는 본문뿐 아니라 첨부(EX-99.1 보도자료, EX-10 계약서 요약·물량·기간·고객명)를 연다. 보도자료는 본문 속 고객·파트너·수치를 본다. 논문은 저자 소속(기업 연구소)과 수치 결과를 본다. 3자 보도자료 = 고객·파트너·정부가 낸 발표에서 다른 기업(특히 한국 기업·미국 중소형주)이 드러나는 것 — 이런 '숨은 이름'이 미보도일 가능성이 가장 높다.
   - robots.txt가 막은 곳(Nature 계열·Seeking Alpha·Motley Fool·Reuters 등 기사 사이트)은 열지 않는다.
   - **미보도 확인(반드시)**: 고른 원문마다 회사명·제품명·핵심 수치로 (1) 영어권 웹 검색(Reuters·Bloomberg·WSJ·CNBC·업계지 포함) (2) 국내 언론 검색(한국어 회사명·제품명으로 네이버 뉴스 등) 을 둘 다 한다. **어느 쪽이든 같은 사실을 보도한 기사가 있으면 버린다** — 국내 언론에 이미 나온 것은 가져오지 않는다. 보도는 없고 회사 자체 발표만 있으면 통과. 검색으로 확인한 범위(검색어·날짜)를 기록한다.
   - 그다음 기준: 미국 상장사 연결(티커) / 한국 기업 연결은 있으면 가점 / 숫자로 말할 수 있는 경제적 의미 / 지금 써야 할 이유 / 엔지니어 관점 해석 여지. 정기 실적·10-Q는 숫자가 놀라울 때만.
   - 같은 원본을 다시 보내지 않는다: outputs/article/sources/log.csv의 url과 대조(없으면 머리행 `date,time_kst,url,source_class,title,yama,sent`부터 만든다).
   - 미보도 원문이 없으면 억지로 채우지 않는다 — 메시지에 "미보도 원문 없음(검토 n건, 보도 확인으로 제외 m건)"이라고 쓴다.
   - 기록: outputs/article/sources/<YYYYMMDD>.md에 덧붙이고 log.csv에 행 추가(③ 파이낸싱도 같은 log.csv, source_class '파이낸싱').

1-2. ③ AI 파이낸싱 — sources 중 source_class '파이낸싱'(config/financing_watch.yaml 발행사의 SEC 424B·FWP·S-3ASR·8-K 2.03·3.02 등 + 자금 조달 제목의 보도자료·9개 매체 기사). **미보도 규칙을 적용하지 않는다** — 이미 보도됐어도 가져온다. 값어치는 자본 구조·조건·참여자에 있다.
   - 같은 사건(발행사·증권·날짜)은 한 건으로 묶는다. 이미 보낸 사건은 새 사실(참여자·클래스·규모·가격·조건 변경)이 있을 때만 '갱신'으로 다시 보낸다(log.csv source_class '파이낸싱'으로 대조).

   - 적는 것: 발행사 / 증권 종류(보통주 클래스 A·B·C, 의무전환 우선주·예탁증권, 전환사채, 회사채 만기·쿠폰, 사모 신용·SPV·리스 금융, 선도 매도) / 규모(기본+초과배정) / 가격·할인율·전환 조건 / 인수단 / **앵커·전략적 투자자**(누가 얼마) / 자금 용도(CAPEX·데이터센터·칩 구매) / 희석률(신주 ÷ 기존 주식 수).
   - **직전 발표 대비 바뀐 점**을 반드시 비교한다: 처음 알려진 계획(회사 발표·S-3ASR·첫 보도)과 최종 서류의 차이 — 예: 클래스 C 계획 → 클래스 A 발행, 전략적 투자자 합류, 규모·가격 변경. 비교할 직전 자료가 없으면 '직전 대비 미확인'.
   - 밸류체인 함의 한 줄: 돈이 어디서 어디로(예: 칩 공급사가 고객의 증자에 참여 → 고객이 그 돈으로 칩을 산다 = 순환 구조·벤더 파이낸싱). 금지표 '협력·MOU → 매출 확보', '고객 투자 확대 → 특정 공급사 매출'을 지킨다 — 공급 계약·물량이 확인되지 않으면 '매출 연결 미확인'.
   - 자금 조달 시장 신호(대형 증자·채권·사모 신용의 규모·금리·수요, 철회·연기)는 'AI CAPEX 자금줄' 관점으로 한 줄. 주가 영향은 단정하지 않는다.

3. 텔레그램 — 한 회차 1통에 ①·③·②를 함께(레벨 'PULSE'가 없으면 'PITCH'). 텍스트 파일 outputs/article/sources/<YYYYMMDD_HHMM>_tg.txt를 먼저 쓰고 `py -c "import sys; sys.path.insert(0,'radar'); import notify; notify.send(open(r'<파일>',encoding='utf-8').read(), 'PITCH')"`.
   - 보내는 조건: ④ 새(또는 갱신된) 숏 리포트가 1건 이상이거나 ① 미보도 원문이 1건 이상이거나 ③ 새(또는 갱신된) AI 파이낸싱 사건이 1건 이상이거나 ② 새로 알파 5.0 이상이 된 종목이 1개 이상일 때. 모두 없으면 보내지 않는다(기록만).
   - 형식:
     `[치입 펄스 HH:MM]`
     `■ 숏 리포트 n건`(있을 때 맨 위) — 건마다 `① 대상(티커) ← 운용사 — 핵심 주장 한 줄` / `주장별 검증: ①…확정/일부/반박/불가(근거)` / `밸류: 핵심 변수·손익분기값 vs 현재 가격·컨센서스` / `수급: 락업·내부자 매도·실적일` / `다음 확인: 사건(날짜)` / `원문: 리포트·1차 서류 URL`.
     `■ 미보도 원문 n건` — 건마다 `① 제목 — 원본 유형(논문·보도자료·3자 보도자료·SEC 8-K·정부)·발표 주체·시각(KST, 현지 병기)` / `새로운 것: 한 줄` / `의미: 숫자·누가 유리/불리(티커)` / `야마 후보: 한 줄` / `보도 확인: 영어권·국내 검색 결과 없음(검색어)` / `원문: URL`. 없으면 `■ 미보도 원문 없음(검토 n건 · 이미 보도돼 제외 m건)`.
