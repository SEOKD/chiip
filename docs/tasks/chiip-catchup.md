# chiip-catchup — 예약 작업 누락 재실행 (마스터 지시 2026-11-04 "각 기능이 주기대로 실행 실패하면 넘어간 태스크를 반드시 재시행하는 구조")

3시간마다 20분(00·03·06·09·12·15·18·21시, 마스터 지시 2026-11-08 — 이전 매시간 20·50분). 누락 탐색은 지난 24시간이라 주기가 길어도 빠지지 않는다. 판정은 `scripts/ops/catchup.py`가 한다. 모델은 목록을 받아 저장하고, 재실행을 부르는 일만 한다.

1. `list_scheduled_tasks`를 부른다. 켜진 작업마다 `list_task_runs`를 한 번씩 부른다. 자기 자신(chiip-catchup)은 빼고, 1회성 작업도 뺀다.
2. `{"now": "<지금 KST ISO>", "tasks": [목록 행에 "runs": 실행 목록을 더한 것]}`을 `radar/state/catchup_in.json`에 쓴다(git 제외). 그다음 `py scripts/ops/catchup.py radar/state/catchup_in.json`을 실행한다.
3. 결과의 `rerun` 항목마다:
   - `run_scheduled_task`로 다시 실행한다.
   - 바로 뒤에 `py scripts/ops/catchup.py --mark <taskId> <slot>`을 실행한다. 같은 회차는 두 번 돌리지 않는다.
4. `rerun`이 있을 때만 텔레그램을 한 번 보낸다. 형식은 `[Chiip Ops] 누락 회차 재실행: <작업 이름> <회차 KST>(실행 기록 없음|실패)`이고, 발송은 `notify.send(..., "OPS")`로 한다. 없으면 아무것도 보내지 않는다.
5. 같은 작업이 3회 연속 재실행 대상이면 재실행은 계속한다. 다만 텔레그램 끝에 `반복 누락 — 원인 점검 필요` 한 줄을 붙인다(판정 기록 `radar/state/catchup.json`).

- 고빈도 작업(Pulse 10분, Ten-bagger 30분, Midterm 3분)은 놓친 회차를 하나하나 메우지 않는다. 가장 최근 회차가 비었을 때만 한 번 돌린다. 다음 회차가 앞 회차의 일을 이어받기 때문이다.
- 재실행된 작업은 원래 지시문대로 돈다. 산출물의 날짜·회차 표기는 실제 실행 시각 기준이고, 재실행이라는 사실은 Ops 알림에만 적는다.
- `stale`(24시간이 지난 누락)는 재실행하지 않는다. 알림에 `오래된 누락: <작업> <회차>` 줄만 붙인다.
- 무인 실행에서 앱이 `run_scheduled_task`를 거부하면 그 작업을 텔레그램에 `재실행 거부 — 앱에서 지금 실행 필요: <작업>`으로 적는다. 이 경우 `--mark`는 하지 않는다. 다음 회차에 다시 시도하기 위해서다.
