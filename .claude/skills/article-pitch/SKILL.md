# article-pitch — 기사 소재 (ADR-010 §7)
## 재료 (지난 24시간)
- **먼저 후보 풀(2026-11-08 보완):** `py scripts/article/pitch_pool.py` — Pulse 피드 판단 건(인사이트 4 이상)·P0·P1 알림·새 IR 문서(일본·한국·대만·홍콩·유럽 Fiscal)·SEC·DART·오늘 Industry 리포트를 모아 '1차 문서 있음 3 + 한국 연결 2/1 + 인사이트 + 숫자'로 순위를 매기고, 최근 7일 기사 소재·마스터 딘스티커 종목은 깎는다. 상위 후보부터 1차 문서를 열고 신규성 검색을 한다 — 찾기에 시간을 쓰지 않는다. 풀에 없는 재료도 아래 목록에서 더할 수 있다.
- `radar/cards/` P0~P2 카드, `radar/reverse/signals/` 수렴·S3 이상, 정책·학회 항목, SEC 공시·실적, 포커스 점수 급변, `insight-review` 결과, `model-lab` 노트(산업 데이터 논문).

## 고르는 기준 (`yama-check` 4요소 + 부가가치)
1. 신규성: 9개 지정 매체·국내 주요 매체에 **아직 없는** 각도인가(검색으로 확인). 이미 보도됐으면 후속 각도가 있을 때만.
2. 한국 기업 연결: T0·한국 후보 종목의 실적 동인에 닿는가.
3. 경제적 의미: 숫자(매출·물량·점유율·CAPEX)로 말할 수 있는가.
4. 지금 써야 할 이유: 시점(실적·정책 단계·학회).
5. 부가가치 원천: 독점(역방향 흔적)·해석(양산 관점)·속도·정량 중 무엇인가. 없으면 제외.

## 형식 (텔레그램 1통 — `py scripts/article/pitch_feedback.py send <YYYYMMDD>`가 `_tg.txt`를 채택 버튼과 함께 보낸다, 2026-11-08) — 마스터 지시 2026-10-30 "양식이 너무 난잡하다"
```
[기사 소재 MM/DD] 3건

기사①
■ 야마 한 문장
- 뉴팩트
- 본론1
- 본론2
- 본론3
- 결론

기사②
■ …
```
- `야마:`·`뉴팩트:`·`본론:`·`한국 연결:` 같은 줄머리 라벨을 쓰지 않는다. 순서가 곧 구조다: ■ 줄 = 야마, 첫 `-` = 뉴팩트(이번에 처음 나온 숫자·서류·발언), 다음 셋 = 본론(인과 고리·숫자·파급), 마지막 = 결론(그래서 무엇이 달라지나·다음 확인 사건 날짜).
- 한국 전자산업 기업과의 연결은 따로 항목으로 빼지 않는다 — 야마와 본론 전개 안에 자연스럽게 넣는다(마스터가 취재하는 영역이라 당연한 전제).
- 한 줄 = 한두 문장, 숫자는 단위·기간을 붙여서. 기사 사이는 빈 줄 하나. 링크·검색어·내부 코드·등급은 넣지 않는다.
- 후보가 없으면 보내지 않는다(잡음 금지).
- **텔레그램에서 뺀 항목은 기록 파일에 남긴다**(아래 '기록'): 1차 출처 링크·신규성 검색 기록(검색어·날짜·검색처)·보강 취재 질문·데스크 킬 질문·틀리는 조건·부가가치 원천(독점·해석·속도·정량). 프로바이저 지시(D-·X-)가 요구하는 줄도 기록 파일에만 쓴다.

## 기록
- `outputs/article/pitch/YYYYMMDD.md`(로컬 상세. 필드 인텔과 맞닿는 메모는 여기만) — 기사마다 1차 출처 링크·신규성 검색 기록·보강 취재 질문 3개·데스크 킬 질문·틀리는 조건·다음 확인 사건·부가가치 원천을 적는다(텔레그램 양식에서 뺀 항목, 성적표·프로바이저 점검 재료).
- `outputs/article/pitch/YYYYMMDD_tg.txt` = 텔레그램 본문 그대로.
- `outputs/article/pitch/log.csv`(date,pitch_id,yama,sources,adopted) — adopted는 비워 둔다. 마스터가 텔레그램 버튼(① 채택·모두 패스)을 누르면 `radar/telegram_inbox.py`가 채운다(2026-11-08). 대화로 채택을 말하면 같은 칸에 '채택'. 프로바이저 채택률은 답한 칸만 센다. pitch_id는 `PITCH-YYYYMMDD-NN`(텔레그램 기사 순서와 같게 — 버튼이 번호로 찾는다).

## 금지
- 텔레그램에 필드 인텔·엠바고·취재원 단서. 확인 안 된 단정("단독 확인" 등). 정황을 사실처럼 쓰기.

노션 자료 참조(필수, 2026-11-01 마스터 지시): 후보 종목마다 `docs/channels/notion.md` '노션 자료실'대로 `py radar/notion_library.py --need <회사>`의 PDF·xlsx 요지와 `notion-search` 게시글을 참조한다. IB 리포트 내용은 취재 단서이고 기사 문장으로 옮기지 않는다.

공개 텔레그램 채널(2026-11-01 마스터 지시): `py radar/pollers/tg_channels.py --recent 24`와 `--about <이름>`을 단서로 쓴다. 채널 글은 취재 단서이고 1차 확인 전에는 기사 근거가 아니다(`docs/channels/telegram.md`).

링크드인(2026-11-01 마스터 지시): 자동 수집하지 않는다. 마스터가 노션 Informations 'LinkedIn' 페이지에 옮겨 둔 글만 `notion-search`로 읽어 단서로 쓰고, 작성자 이름은 쓰지 않는다(`docs/channels/notion.md`).

**무역·PPI(마스터 지시 2026-11-02):** 기사 소재의 경제적 의미를 수치로 뒷받침할 때 쓴다. 공식 통계이므로 출처 기관을 적는다. 필요할 때 `py radar/trade_ppi.py --status`(또는 `--need <회사 id>`)로 7개 지역 세부 지표를 본다. PPI 전년비·수입처 변화가 판단을 바꿀 때만 쓰고, 나열하지 않는다. 별표는 업종 대용 지수다. 값이 없으면 '미확인'이다.

**HS 급등 품목(2026-11-02 마스터 지시):** `py radar/trade_hs.py --surge`(급등 품목), `--series <hs>`(시계열), `--company <회사 id>`(이 회사 BOM 품목과 겹치는 급등)를 필요할 때 본다. 수출입 급등은 단서이고 금지표대로 특정 기업 매출로 바로 잇지 않는다. 금액 증가는 가격과 물량을 나누지 않은 값이다.
