# earnings-delta — 실적·콜 변화 분석

## 입력
- 이번 분기 자료(실적 발표문·슬라이드·콜 스크립트) — `source-ingest`로 먼저 등록
- 비교 기준: 직전 분기 같은 자료, 회사 가이던스, 컨센서스(있으면), 관련 테제·주장

## 수동 입력 자료 (마스터 노션 2026-10-28)
- 컨센서스·한국 어닝콜은 마스터가 노션 Informations > 'Consensus · Earnings Call' DB(`config/notion.yaml` pages.consensus_intake)에 넣는다. 미국·유럽 어닝콜은 Fiscal.ai company_ir_events_transcript(`scripts/fiscal/templates/transcript_qa.js` — 화자·Q&A 구간)·company_earnings_summary로 치입이 직접 받는다(요지만, 인용 15단어 이하).
- 처리: 상태 '입력 완료' 행을 읽어 → 컨센서스 숫자는 `knowledge/models/valuation/manual_consensus.csv`(as_of,id,period,fy_end,eps_avg,eps_low,eps_high,n_analysts,rev_avg,source,note)에 한 행씩, 어닝콜은 자기 말 요지로 비교 기준에 사용 → 노션 행 상태 '치입 반영', 치입 메모에 반영 내용 한 줄. 원문 문장·표를 저장소에 옮기지 않는다.
- 필요한 종목이 DB에 없으면 '요청' 상태로 새 행을 추가해 마스터에게 요청한다(우선순위: 알파 5.0 이상 → v2 이관 종목 → 참고).

## 절차
1. **주제별 발언 추출** — 표준 주제: 수요(최종 시장별) / 물량(출하·비트그로스) / 가격(ASP) / 믹스 / 가동률·재고 / 원가·수율 / CAPEX·증설 / 제품·기술 로드맵 / 고객·인증 / 가이던스 / 리스크.
   각 발언에 `source_id + locator(쪽·분)` 기록.
2. **직전 분기와 대조** — 같은 주제의 직전 발언을 찾아 나란히 놓는다. 비교 표:
   | 주제 | 직전(위치) | 이번(위치) | 변화 | novelty |
   novelty: 신규 / 수정 / 반복 / 재해석 / 미확정 (claim-intake 기준과 같음).
3. **신규성과 중요성을 따로 점수화** (각 0~3)
   - 신규성: 0 반복 · 1 표현만 변화 · 2 수치·시점 변화 · 3 처음 나온 정보
   - 중요성: 0 실적 동인과 무관 · 1 간접 · 2 특정 사업부 동인 · 3 회사 전체 이익·테제 핵심
   - 신규성 높고 중요성 낮은 것을 헤드라인으로 올리지 않는다.
4. **숫자 점검** — 단위·기간·회계기준(GAAP/비GAAP, 연결/별도)·환율 기준일 명시. 비교 불가면 "비교 불가".
5. **상용화 상태 변경** — 제조·고객·사업 축별로 이동한 항목만.
6. **테제 영향** — 관련 `knowledge/theses/` 고리별: 강화 / 약화 / 무관, 근거 위치.
7. **금지표 검사** — "고객 투자 확대 → 우리 매출", "샘플 → 양산" 같은 회사 측 화법을 그대로 옮기지 않았는지.
8. **주장 승격** — 신규성 ≥2 또는 중요성 ≥2 항목을 `claim-intake`로 등록.
9. **시장 반응**(가능할 때만): 발표 다음 거래일 종목·업종 지수 대비 등락. 확인 못 하면 "미확인".

- 마지막 단계: 실적 반영 후 수집·계산(`py radar/markets/valuation_data.py --force`) → `valuation-card <기업 id>`로 시나리오·반영도 갱신(invest 모드 경계 준수, report 출력과 분리).

## 출력 (report 모드)
```
[모드: report / 범위: <기업> <분기> 실적·콜 / 기준시각: …]
결론(2~3문장)
변화 표(주제·직전·이번·변화·신규성·중요성)
상용화 상태 변경
테제 영향
반대 검증: 회사 화법 중 검증 안 된 연결
다음 확인 사건
종료 상태: 판단 가능 / 조건부 판단 / 핵심 근거 부족
```
저장: `outputs/report/YYYYMMDD_<entity>_<분기>_earnings-delta.md`

## 완료 기준
모든 변화에 양쪽(직전·이번) 위치 인용. 수치 단위 일관.

## 흔한 실수
- 직전 분기 자료 없이 "이번에 처음 언급" 단정 → 직전 자료를 반드시 확인.
- 가이던스와 실적 혼동.
- 경영진 낙관 표현을 확정 사실로 저장(claim_type은 가이던스).
