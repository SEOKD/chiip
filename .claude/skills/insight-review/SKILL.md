# insight-review — 인사이트 검토 (ADR-010 §1)
목적: 마스터의 판단을 **같은 강도로** 검증해 더 강하게 만든다. 칭찬도 반대도 근거로만. 마스터 가설에 동조하는 쪽으로 기울지 않는다.

## 0. 대상 찾기 (노션 커넥터 — `config/notion.yaml` pages)
마스터 노션 구조(이름·역할 고정): **Insights**(마스터 글 = 검토 대상) · **Informations**(수집 정보 = 근거 재료) · **Stocks**(종목·테마 커버리지 = 종목 맥락).
- `pages.insights.id`를 fetch → 하위 페이지 목록(제목 YYMMDD). 각 하위 페이지를 fetch해 `page_last_edited_at`을 얻고 `py scripts/insight_state.py check <id> <수정시각>` → DUE만 검토. 하위 페이지 중 '치입 검토'로 시작하는 것은 치입 기록이므로 건너뛴다.
- 글에 등장하는 종목은 **Stocks**의 해당 페이지('회사명 티커')를, 근거 주제는 **Informations**의 관련 페이지를 함께 읽는다(notion-search에 page_url로 범위 지정).
- (구) '오피니언·인사이트' DB(`insights_db`)에 마스터가 새 글을 쓰면 그것도 검토한다(속성 갱신 규칙은 7단계 하단).

## 1. 경계 확인 (먼저)
- 글에 필드 인텔·엠바고·취재원 단서가 보이면: 정량 판정은 공개 근거로만 하고, **필드 인텔 대조 결과는 로컬 `outputs/report/insight/`에만** 적는다(노션 검토 페이지에 쓰지 않음). F4 단서는 추상 포인터로도 노션에 쓰지 않는다.
- 노션 검토 페이지 = report 모드(목표주가·매수 의견 없음).

## 2. 분해 — 인과 사슬
- 글의 결론을 1문장으로 다시 쓴다(마스터 문장과 다르면 차이 표시 — `reframe-check` 원리).
- 결론에 이르는 고리를 3~7개로 쪼개고, 고리마다 claim id 또는 '미확인'. 금지표(CLAUDE.md) 해당 고리 표시.

## 3. 정성 평가 — 10점, 분리 채점 (각 1문장 이유 + 감점 요인 + 상향 조건)
| 축 | 질문 |
|---|---|
| 논리 | 고리가 끊김 없이 이어지나, 금지표 위반은 |
| 사업 경쟁력 | 대안 대비 성능·비용·실행력, 공급 관계 실재 |
| 투자 매력 | 실적 동인에 닿나, 크기·시점 |
| 증거 확신도 | 1차 출처 비율, 독립 확인 수(`origin_id`) |
| 신규성 | 컨센서스·기존 보도와 무엇이 다른가(`consensus-gap`) — 다르지 않으면 낮게 |
| 기사 가치 | `yama-check` 기준 |
- 종합 점수는 평균이 아니라 '가장 약한 고리'를 반영해 판단(이유 명시).

## 4. 정량 평가 — IB 모델 (invest 모드 계산, 출력은 report 모드 표현)
1. 인사이트를 **모델 입력 변화**로 번역: 물량·ASP·점유율·마진·CAPEX·시점 중 무엇이 얼마나(`valuation-bridge` 다리 식).
2. 영향 받는 종목별로 EPS·FCF 변화 → 가치 변화: 하위 섹터 기본 방법(`config/valuation.yaml` subsectors) + DCF 교차. 할인율·장기 P/E는 파라미터 등록부 id로 인용(예: `prm-val-tpe-memory`).
3. **가격 내포 기대** 비교: 엔진 `implied_growth`·`priced_in`(있으면) 또는 역DCF로 "현재 주가가 가정하는 성장".
4. 출력 한 줄: "맞으면 가치 차이 ○%(기본)·범위 ○~○% / 시장 반영 추정 ○% / 남은 갭 ○%p" + 시나리오 확률(약세·기본·강세)과 비대칭.
5. 데이터가 없으면(가격·추정치 미수집) 숫자를 채우지 말고 "정량: 핵심 근거 부족(필요: …)"으로 둔다. 미국 종목 재무는 `knowledge/models/fundamentals/us/`(SEC XBRL)로 계산할 수 있다.

## 5. 반대 검증 (`red-team` 서브에이전트에 결론문 + claim id 전달)
- 가장 약한 고리, 대안 설명, 이미 반영됐을 가능성, 역방향 신호 독립성. 판정: 유지 / 조건부 / 수정 필요 / 근거 부족.

## 6. 반증 조건·다음 확인 사건·예측 등록
- 측정 가능한 예측 1~3개를 `prediction-log`로 등록: 마스터 확률(글에 있으면)과 치입 확률을 **각각** 행으로(`owner`, `origin`=노션 URL). 글에 확률이 없으면 치입 행만.

## 7. 기록
- 노션: 검토한 Insights 글 **아래 하위 페이지** `치입 검토 YYYY-MM-DD` (결론 → 인과 사슬 → 정성 표 → 정량 → 반대 검증 → 반증 조건·다음 확인 → 종료 상태 → 부가가치 원천). 마스터 글 본문은 한 글자도 고치지 않는다.
- 기록 후 원 글을 다시 fetch해 그때의 `page_last_edited_at`으로 `py scripts/insight_state.py mark <id> <수정시각> <검토 페이지 URL>`.
- (구) DB 글이면 속성 `치입 판정`·`정성 점수`·`정량 갭`·`검토일` 갱신, `검토 요청` 해제.
- 로컬: `outputs/report/insight/YYYYMMDD_<제목>.md` (노션과 같은 내용 + 로컬 전용 대조가 있으면 별도 절).
- 텔레그램(`notify.send(text, "REVIEW")`): `[인사이트 검토] 제목 — 판정 · 정성 ○.○ · 정량 갭 ○` (본문·필드 인텔 없음).
- Informations의 채널체크·IB 리포트 요지를 근거로 썼다면: IB 요지는 라이선스 자료라 노션 검토 페이지에 문장을 옮기지 말고 '마스터 Informations 페이지 참조'로만 가리킨다. 채널체크(필드 인텔 가능성)는 정량 판정 근거로 쓰지 않고 로컬 파일에서만 대조한다.
- 검토에서 나온 기사 소재·텐배거 후보는 `article-pitch`·`tenbagger-card` 재료로 넘긴다.

## 금지
- 마스터 글 본문 수정(검토는 하위 페이지·속성만). 근거 없는 동조나 반대. 정량 칸을 추정으로 채우기. 노션 검토 페이지에 local-only·필드 인텔 대조.
