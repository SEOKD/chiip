# 소비재 트렌드 파이프라인 설계안 — TickerTrends형 (초안, 마스터 승인 전)

작성 2026-11-14 KST. 마스터 지시 "TickerTrends처럼 소비재 트렌드를 파악할 만한 파이프라인을 고민하라".
상태: **설계안**. 구현은 마스터 승인 후 단계별로 한다(계획 → 승인 → 실행 → 보고).
- 2026-11-14 마스터 "A단계 진행" → **A 완료**. 아래 §1 진단은 착수 전 상태다.
  - 수집 공백: 원인은 11-11 `run_hourly` 시간 예산 수리로 이미 해소됐다(그 뒤 매일 기록).
  - 애플: 개발사 id 학습을 고쳤다.
  - 위키: 44개 문서를 2015-07부터 백필했다(개명 6건 합산).
  - 수입: 소비재 8개 품목의 나라별 미국 수입을 2016-11부터 적재했다.
  - 다음은 C(나우캐스트)이며 승인 대기다.

## 0. 결론
- TickerTrends의 가치는 세 층이다.
  - ① 키워드가 먼저 뜨고 종목이 나중에 붙는 **바텀업 발굴**
  - ② 종목별 대체 데이터 **추적**
  - ③ 대체 데이터로 발표 전 KPI를 맞히는 **KPI 나우캐스트**
- Chiip에는 ②의 일부만 있다(`radar/consumer_attention.py`, 30개사 지도). ①과 ③이 없다.
- ③이 없으면 관심도는 '관심'에 그친다. 금지표의 '관심 증가 → 매출'을 넘지 못한다.
- 따라 하지 않을 것: 틱톡·인스타그램·아마존·카드 결제 데이터. 약관·robots·자격 문제로 못 쓴다. 숏폼 바이럴의 초기 포착은 TickerTrends를 이길 수 없다.
- 이길 수 있는 곳은 세 군데다.
  - **물건**: 수입 통계
  - **한·일 1차 자료**: 네이버 데이터랩·라쿠텐·관세청·e-Stat
  - **역사가 긴 공개 원천**: 위키 조회수 2015년~
- 포지셔닝은 **'아시아 소비재 + 무역 흐름 나우캐스트'**다.

## 2. 설계 — 4단계

### A. 수리·백필 (키 불필요, 먼저)
1. 수집 공백 원인을 찾아 고친다. 애플 개발사 id 자동 학습도 고친다.
2. **위키 조회수 백필.** 지도의 모든 문서를 2015-07부터 일별로 받는다. Wikimedia per-article API는 robots 제한이 없다. → 40개 분기 역사.
3. **수입 통계 상대국 분리.**
   - `trade_hs`의 미국 Census 조회에 소비재 HS 소수만 상대국별로 추가한다.
   - 대상 HS: 3304·3305·1902·2106·9503·9504·6403·6404·3401.
   - 상대국: 한국·일본·중국·대만·프랑스.
   - 일본 e-Stat 나라별 수출도 같은 품목으로 본다.
   - 이것이 '물건이 말보다 먼저'다. 예: 한국산 화장품 대미 수입 → K뷰티 셀인(sell-in, 유통 채널로의 출하).

### B. 바텀업 발굴 (키워드 → 종목)
1. **입구.** 새 진입과 순위 급상승만 본다.
   - Wikimedia 일별 상위 1,000 문서(`/metrics/pageviews/top/`, en·ja·ko·zh, 2026-11-14 응답 200 확인)
   - Google Trends 급상승: `radar/retail_channels.py`에 이미 있다.
   - 애플 차트: 이미 수집 중이다.
2. **분류.** 사람·사건·스포츠 경기는 뺀다. 상품·브랜드·IP·게임·앱만 남긴다.
3. **매핑.** 브랜드 → 소유·제조·개발·배급 회사 → 상장 코드.
   - Wikidata 항목 JSON을 쓴다(`Special:EntityData/*.json`, robots 허용). SPARQL(`/sparql`)은 robots가 막아 쓰지 않는다.
   - 쓰는 속성: P31(종류), P127·P176·P178·P123·P749(소유·제조·개발·배급·모회사), P414·P249(거래소·티커).
   - 문서 제목 → Q-id 경로는 구현 때 robots를 다시 확인한다. Wikipedia `/w/api.php`는 일반 크롤러가 막혀 있다.
4. **중요도 관문.** 금지표 '브랜드 인기 → 모회사 실적'을 막는다.
   - 브랜드가 모회사 매출의 10% 이상이거나 사업부로 공시될 때만 후보로 올린다.
   - 대형 복합 기업의 한 브랜드는 집계만 하고 발굴 후보로 올리지 않는다.
5. 매핑은 가설이다. 근거·반대 근거를 단다. 통과분은 `config/consumer_auto.yaml`과 Ten-bagger 일요일 선별에 합류한다.

### C. KPI 나우캐스트 (핵심 — 가치가 나는 곳)
1. 회사마다 목표 KPI를 하나 정한다(매출 YoY·동일점 매출·판매량·MAU). 실적값은 Fiscal.ai 1순위에서 받는다.
2. 신호 → KPI 회귀를 시차와 함께 푼다.
   - 신호: 위키 백필, 상대국 수입, 승인되면 검색량.
   - 중첩 표본 외 검정(`scripts/fit/stepwise.py`)을 통과한 회사만 채택한다.
   - 상수는 `registry.yaml`에 `prm-consumer-nowcast-*`로 등록한다.
3. 출력: '나우캐스트 대 컨센서스' 차이와 그 범위(표본 외 오차).
   - 실적 2~3주 전에 범위 밖 차이가 나면 Pulse 🛍 '수요 나우캐스트'로 보낸다.
   - 실적 뒤에는 브라이어 점수 장부에 판정을 적는다(월 1회 성적표).
4. 검정에 떨어진 회사는 관심 지표로만 남긴다. 숫자를 만들지 않는다.

## 3. 마스터 결정 필요 — robots와 공식 API
- 아래 공식 API는 키·약관이 있는 문서화된 API이지만, 호스트 robots.txt가 모든 크롤러를 막는다(2026-11-14 확인).
  - `api.steampowered.com`: 스팀 동시 접속자 — 게임 수요의 가장 직접적인 일별 지표
  - `api.twitch.tv`: 게임별 시청자
  - `openapi.naver.com`: 데이터랩
- 지금 선례는 API에도 robots를 적용한다(애플 조회 API는 robots가 `/search`만 막아 id 조회만 쓴다).
- 정해 주셔야 할 것: ① 지금처럼 robots를 엄격하게 적용해 셋 다 뺀다 ② 키를 받는 공식 API는 약관을 기준으로 삼는다.
- Chiip은 법률 판단을 하지 않는다.
- Tranco(웹 트래픽 순위)는 robots가 `/list/`·`/api`를 막아 제외한다.

## 4. 못 하는 것 (정직한 공백)
- 틱톡·인스타그램: TikTok Research API는 비영리 학술 연구자 대상(자격 확인 필요). 웹 수집은 금지다.
- 아마존: robots가 ClaudeBot을 막는다(2026-10-30 결정 유지).
- 카드 결제·영수증 패널: 유료다(무료 경로 없음).
- 그래서 숏폼에서 시작한 바이럴은 위키·검색에 나타난 뒤에야 잡힌다. 지연 폭은 B단계 백테스트로 잰다(가설, 미측정).
